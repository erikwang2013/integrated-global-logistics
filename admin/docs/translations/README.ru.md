## Быстрый старт

### 1. Установка зависимостей

```bash
composer install
```

### 2. Настройка переменных окружения

Скопируйте и отредактируйте переменные окружения (необязательно: если они не заданы, используются значения по умолчанию из `config/*.php`):

```bash
cp .env.example .env
```

Ключевые параметры:

| Переменная окружения | Описание | Значение по умолчанию |
|---------|------|--------|
| `JWT_SECRET` | Секрет подписи JWT | `open-admin-jwt-secret-change-in-production` |
| `HASHIDS_SALT` | Соль Hashids | `open-admin-hashids-salt-2026` |
| `ENCRYPTION_KEY` | Ключ шифрования API | 32-байтовое значение по умолчанию |
| `SNOWFLAKE_DATACENTER_ID` | ID дата-центра (0-31) | `1` |
| `SNOWFLAKE_WORKER_ID` | ID рабочего узла (0-31) | `1` |
| `SCOUT_HOSTS` | Адрес ES | `http://localhost:9200` |

**В производственной среде обязательно замените все ключи на случайные строки.**

### 3. Установка в один клик

После запуска сервиса откройте в браузере мастер установки, чтобы инициализировать базу данных и создать администратора:

```bash
php start.php start
```

По умолчанию сервис слушает `http://0.0.0.0:8787` (порт можно изменить в `config/server.php`).

Откройте в браузере **`http://localhost:8787/install`** и заполните поля мастера:

| Шаг | Содержимое |
|------|------|
| ① Конфигурация БД | Хост, порт, имя БД, пользователь, пароль |
| ② Настройки администратора | Имя пользователя и пароль администратора (по умолчанию admin / admin888) |

После нажатия «Начать установку» автоматически создаются таблицы, заполняются данные прав, создаётся учётная запись администратора и в `.env` записывается конфигурация БД.

> После установки создаётся файл блокировки `runtime/install.lock`. Для повторной установки удалите этот файл.

### 4. Вход в систему

Откройте `http://localhost:8787` и войдите с учётными данными администратора, заданными при установке.

### 5. Запуск фронтенда (необязательно)

**Flutter-админка (Web):**

```bash
cd apps/flutter
flutter pub get
flutter run -d chrome    # Веб-версия (в стиле PC-панели управления)
```

**Клиент HarmonyOS (мобильный):**

Откройте каталог `apps/harmonyos/` в DevEco Studio и запустите на реальном устройстве или эмуляторе.

### 6. Развертывание в один клик через Docker Compose (рекомендуется для продакшена)

Проект содержит полную Docker-оркестрацию из 5 сервисов: Nginx, PHP (приложение webman), MySQL, Redis, Elasticsearch.

```bash
# 1. Настройте переменные окружения для Docker
cp .env.docker .env

# 2. Запустите все сервисы
docker-compose up -d

# 3. Откройте мастер установки в браузере
# http://localhost:8787/install  (укажите данные БД и администратора)
# или выполните SQL-миграцию вручную (внутри контейнера app):
# docker-compose exec app mysql -h mysql -u root -p < database/install.sql

# 4. Доступ
# http://localhost:8787  (webman)
# http://localhost:8080  (Nginx reverse proxy)
```

- `Dockerfile`: PHP 8.3 + OPcache + Composer, на базе `php:8.3-cli`
- `docker-compose.yml`: оркестрация 5 сервисов, изоляция сети, персистентные тома данных
- `.env.docker`: переменные окружения для Docker


## Стандарты базы данных

- **Префикс таблиц**: `logistics_`
- **Первичный ключ**: во всех таблицах — `id BIGINT UNSIGNED NOT NULL`, **AUTO_INCREMENT запрещён**
- **Генерация ID**: первичные ключи генерируются на уровне приложения через `SnowflakeService::generate()`, уникальны в распределённой среде
- **Обязательные поля**: каждая таблица обязана содержать `id`, `created_at`, `updated_at`
- **Мягкое удаление**: для таблиц с мягким удалением добавляется `deleted_at DATETIME DEFAULT NULL`
- **Чувствительные поля**: телефон, email, номер удостоверения и т. п. автоматически шифруются/расшифровываются плагином `encryptable`; в БД хранится шифротекст в `VARCHAR(500)`

## Документация API

Полный справочник API (единый формат ответов, коды ошибок, все эндпоинты, процесс аутентификации, политика лимитов, цепочка промежуточного ПО) — см. **[docs/API.ru.md](docs/API.ru.md)**. Ключевые моменты:

- **Единый формат ответа**: `{ "code": 0, "message": "success", "data": {...} }`, `code=0` означает успех
- **Коды ошибок**: `400` ошибка параметров / `401` не авторизован / `403` нет прав / `404` не найдено / `422` ошибка валидации / `429` превышен лимит запросов / `500` ошибка сервера
- **Версия API**: задаётся заголовком `API-Version: v1` (по умолчанию v1), в URL не отражается
- **Аутентификация**: `Authorization: Bearer <token>`; access_token действует 2 часа, refresh_token — 14 дней
- **Работа с ID**: ID в запросах/ответах — строки, зашифрованные hashids; реальные ID БД не раскрываются

## О фронтенде

### Flutter-админка (PC-стиль)

- **Макет**: боковая панель (сворачивается 64px/240px) + верхняя панель + область контента, три адаптивные точки (телефон/планшет/десктоп)
- **Страницы**: вход, дашборд, пользователи, роли и права, системные настройки, журнал операций, личный кабинет
- **Управление состоянием**: GetX (синглтон `ApiService` + `AuthService` для персистентности токена)
- **Дашборд**: карточки статистики, линейные графики трендов (fl_chart), круговая диаграмма, последние операции
- **Экспорт**: Excel/PDF; PDF содержит неудаляемую информацию об авторских правах
- **Массовые операции**: массовое удаление по выбору, массовое включение/отключение
- **Тема**: Material 3, светлая/тёмная

### Мобильный клиент HarmonyOS

- **Страницы**: вход, дашборд, список/детали пользователей, личный кабинет
- **Аутентификация**: JWT Bearer + автоматическое бесшовное обновление токена при 401; при неудаче — редирект на страницу входа
- **Хранение**: токен через AppStorage

## Правила разработки

- Глобальные функции/классы — без ведущего `\`, импорт только через `use`
- Каждый PHP-файл должен содержать заголовок с заявлением об авторских правах
- Все конфигурационные файлы должны содержать китайские комментарии с пояснением параметров
- Первичные ключи БД генерируются snowflake на уровне приложения; автоинкремент запрещён
- Все ID в параметрах и ответах API должны шифроваться/расшифровываться через hashids
- Middleware AdminPermission кэширует права пользователя в Redis (TTL=60s), устраняя узкое место запросов N+1

## Развертывание

### Docker Compose (рекомендуется)

В корне проекта — `docker-compose.yml` с оркестрацией 5 сервисов:

| Сервис | Образ | Порт |
|------|------|------|
| `nginx` | nginx:alpine | 80, 443 |
| `app` | локальная сборка из `Dockerfile` | 8787 |
| `mysql` | mysql:8.0 | 3306 |
| `redis` | redis:7-alpine | 6379 |
| `elasticsearch` | elasticsearch:8.x | 9200 |

PHP-образ собирается из `Dockerfile`, базовый образ `php:8.3-cli`, включён OPcache.

```bash
cp .env.docker .env
docker-compose up -d
```

### CI/CD

Пайплайн непрерывной интеграции GitHub Actions: `.github/workflows/ci.yml`

- Проверка синтаксиса PHP (`php -l`)
- Модульные тесты PHPUnit
- Статический анализ Flutter (`flutter analyze`)

### Резервное копирование БД

Каталог `database/backup/`:

- `backup.sh` — резервное копирование mysqldump + gzip, автоматическая очистка бэкапов старше 30 дней
- `restore.sh` — интерактивное восстановление со списком доступных бэкапов

### Безопасная конфигурация Nginx

Для продакшена см. `docs/nginx-security.conf` — рекомендации по усилению безопасности обратного прокси.
