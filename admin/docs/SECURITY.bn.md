## 1. গভীর প্রতিরক্ষা প্যানোরামা

সিস্টেম ৭ লেয়ারের গভীর প্রতিরক্ষা মডেল ব্যবহার করে, বাইরে থেকে ভেতরে লেয়ার-বাই-লেয়ার ম্যালিসিয়াস রিকোয়েস্ট ফিল্টার করে, নিশ্চিত করে যে কোনো একক লেয়ার ব্যর্থ হলেও পরের লেয়ারগুলো ব্যাকআপ হিসেবে থাকে।

সম্পূর্ণ মিডলওয়্যার চেইন নিম্নলিখিত ক্রমে চলে (দেখুন `config/middleware.php`):

```
请求 → Cors → Locale(Accept-Language) → SecurityMiddleware (erikwang2013/security-php, 31种检测器) → RateLimit → [路由组中间件: AdminAuth → AdminPermission → OperationLog] → Controller
```

| লেয়ার | মিডলওয়্যার/মেকানিজম | সুরক্ষা লক্ষ্য |
|----|--------|---------|
| 1 | SecurityMiddleware (erikwang2013/security-php) | ৩১ ধরণের আক্রমণ ডিটেকশন + HTTP মেথড ভেরিফিকেশন + রিকোয়েস্ট বডি সাইজ লিমিট + Content-Type ভেরিফিকেশন + CSRF + IP আক্রমণ এসকেলেশন ব্ল্যাকলিস্ট |
| 2 | Cors | ক্রস-অরিজিন নিরাপত্তা + রেসপন্স সিকিউরিটি হেডার ইনজেকশন |
| 3 | RateLimit | Redis স্লাইডিং উইন্ডো রেট লিমিট, ব্রুট-ফোর্স প্রতিরোধ |
| 4 | AdminAuth | JWT অথেনটিকেশন + ব্ল্যাকলিস্ট লগআউট |
| 5 | AdminPermission | RBAC method.path গ্রানুলারিটি অথোরাইজেশন |
| 6 | OperationLog | অপারেশন অডিট + সোর্স ডিভাইস ট্রেসিং |
| 7 | ডেটা এনক্রিপশন | Hashids ID অবফাসকেশন + Encryptable DB এনক্রিপশন + EncryptionService ট্রান্সপোর্ট এনক্রিপশন |

ফ্রন্টএন্ড তিন স্তরে (Flutter) আলাদা ইনপুট ভ্যালিডেশন আছে, ব্যাকএন্ড কোনো কিছু বিশ্বাস করে না, প্রতিটি স্তর স্বাধীনভাবে প্রতিরক্ষা করে।

## 2. আক্রমণ ডিটেকশন ইঞ্জিন

## 2. আক্রমণ ডিটেকশন ইঞ্জিন (erikwang2013/security-php)

আক্রমণ ডিটেকশন সেলফ-ডেভেলপড SecurityMiddleware (erikwang2013/security-php) থেকে `erikwang2013/security-php` v1.1+ ডেডিকেটেড সিকিউরিটি প্যাকে মাইগ্রেট করা হয়েছে, **৩১টি ডিটেক্টর** প্রদান করে, ৫টি বড় আক্রমণ ক্যাটাগরি কভার করে।

### 2.1 ডিটেক্টর শ্রেণীবিভাগ

**ইনজেকশন আক্রমণ (১১ ধরণ):** XSS, SQL ইনজেকশন, কমান্ড ইনজেকশন, NoSQL ইনজেকশন, LDAP ইনজেকশন, XPath ইনজেকশন, JNDI/Log4Shell, SSI সার্ভার-সাইড ইনক্লুড, GraphQL ইনজেকশন, SSTI টেমপ্লেট ইনজেকশন

**প্রোটোকল ও রিকোয়েস্ট আক্রমণ (৯ ধরণ):** SSRF, XXE, HTTP রেসপন্স হেডার ইনজেকশন, Host হেডার আক্রমণ, Request Smuggling, Open Redirect, CORS বাইপাস, WebSocket হাইজ্যাকিং, DNS Rebinding

**HTTP প্রোটোকল লেয়ার ভেরিফিকেশন (৬ ধরণ):** HTTP মেথড ভেরিফিকেশন(405), রিকোয়েস্ট বডি সাইজ লিমিট(413), Content-Type ভেরিফিকেশন(415), CSRF Origin চেক, IP আক্রমণ এসকেলেশন ব্ল্যাকলিস্ট, সংবেদনশীল ডেটা লিক ডিটেকশন

**ডেটা ও সিরিয়ালাইজেশন আক্রমণ (৫ ধরণ):** PHP ডি-সিরিয়ালাইজেশন, CSV ফর্মুলা ইনজেকশন, ইমেইল হেডার ইনজেকশন, JWT আক্রমণ (স্ট্রাকচার্ড অ্যানালাইসিস), JS Prototype Pollution

**ফাইল ও পাথ আক্রমণ (২ ধরণ):** পাথ ট্রাভার্সাল, ম্যালিসিয়াস ফাইল আপলোড

### 2.2 প্রসেসিং মোড

প্রতিটি ডিটেক্টর স্বাধীনভাবে দুইটি মোড সাপোর্ট করে:
- `block` — আক্রমণ ডিটেক্ট হলে ব্লক করে, কনফিগার করা স্ট্যাটাস কোড রিটার্ন করে
- `log` — শুধুমাত্র লগ রেকর্ড, ব্লক করে না (`header_injection`, `ssti`, `nosql_injection` ডিফল্ট log মোড, ফলস-পজিটিভ প্রতিরোধে)

### 2.3 IP আক্রমণ এসকেলেশন ব্ল্যাকলিস্ট

একই IP ৬০ সেকেন্ডের মধ্যে ৫ বার আক্রমণ ডিটেকশন ট্রিগার করলে → স্বয়ংক্রিয়ভাবে ১৫ মিনিট ব্যান। স্টোরেজ ব্যাকএন্ড ঐচ্ছিক: Redis (ডিস্ট্রিবিউটেড), File (সিঙ্গেল-মেশিন JSON) বা Cache (হাই-কনকারেন্সি আলাদা ফাইল), বর্তমান কনফিগ Redis স্টোরেজ।

### 2.4 নিরাপত্তা লগ

ফাইল অবস্থান: `runtime/logs/security.log` (অটো রোটেশন, 10MB/ফাইল)

## 4. রেসপন্স সিকিউরিটি হেডার

সব হেডার `Cors` মিডলওয়্যারে ইনজেক্ট হয়, `$response->withHeaders()` দিয়ে প্রতিটি রেসপন্সে যোগ হয়।

| হেডার | মান | কাজ |
|----|-----|------|
| Access-Control-Allow-Origin | `*` | যেকোনো অরিজিনের ক্রস-অরিজিন অনুমতি (ইন্ট্রানেট অ্যাডমিন ব্যাকএন্ড দৃশ্য) |
| Access-Control-Allow-Methods | `GET,POST,PUT,DELETE,OPTIONS` | অনুমোদিত মেথড সেট |
| Access-Control-Allow-Headers | `Authorization,Content-Type` | অনুমোদিত কাস্টম হেডার |
| Access-Control-Max-Age | `86400` | প্রিফ্লাইট রিকোয়েস্ট ক্যাশ ২৪ ঘণ্টা |
| X-Content-Type-Options | `nosniff` | ব্রাউজার MIME স্নিফিং নিষিদ্ধ |
| X-Frame-Options | `DENY` | সব iframe এমবেড নিষিদ্ধ, ক্লিকজ্যাকিং প্রতিরোধ |
| X-XSS-Protection | `1; mode=block` | ব্রাউজারের বিল্ট-ইন XSS ফিল্টার সক্রিয় ও পেজ রেন্ডার ব্লক |
| Referrer-Policy | `strict-origin-when-cross-origin` | একই অরিজিনে সম্পূর্ণ URL, ক্রস-অরিজিনে শুধু ডোমেইন পাঠায় |
| Permissions-Policy | `camera=(), microphone=(), geolocation=()` | পুরো সাইটে ক্যামেরা/মাইক্রোফোন/লোকেশন API নিষিদ্ধ |

OPTIONS প্রিফ্লাইট রিকোয়েস্ট সরাসরি 204 খালি রেসপন্স রিটার্ন করে, পরের মিডলওয়্যার চেইনে প্রবেশ করে না।

### 4.2 Content-Security-Policy (CSP)

অন্যান্য সিকিউরিটি হেডারের সাথে Cors মিডলওয়্যারে ইনজেক্ট হয়, গভীর প্রতিরক্ষা দেয়, ব্রাউজার কী কী রিসোর্স সোর্স লোড ও এক্সিকিউট করতে পারবে তা সীমিত করে।

| হেডার | মান | কাজ |
|----|-----|------|
| Content-Security-Policy | `default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` | স্ক্রিপ্ট/স্টাইল/ইমেজ/কানেকশন/ফ্রেম/ফর্ম ইত্যাদি রিসোর্স সোর্স সীমিত |
| X-Permitted-Cross-Domain-Policies | `none` | Adobe Flash/PDF-এর মতো ক্রস-ডোমেইন পলিসি ফাইল লোড নিষিদ্ধ |

CSP পলিসির মূল পয়েন্ট:
- `default-src 'self'`: ডিফল্টে শুধুমাত্র একই অরিজিনের রিসোর্স অনুমোদিত
- `script-src 'self' 'unsafe-inline' 'unsafe-eval'`: একই অরিজিন স্ক্রিপ্ট + ইনলাইন স্ক্রিপ্ট (Flutter Web-এর প্রয়োজন) + eval (Flutter Web ডিবাগের প্রয়োজন) অনুমোদিত
- `frame-ancestors 'none'`: যেকোনো পেজে iframe এমবেড নিষিদ্ধ, X-Frame-Options: DENY-এর সাথে ডাবল সুরক্ষা
- `base-uri 'self'`: `<base>` ট্যাগ শুধুমাত্র একই অরিজিনে পয়েন্ট করতে পারে
- `form-action 'self'`: ফর্ম শুধুমাত্র একই অরিজিনে সাবমিট হতে পারে

## 5. রেট লিমিট পলিসি

### অ্যালগরিদম

Redis Sorted Set স্লাইডিং উইন্ডো + Lua অ্যাটমিক স্ক্রিপ্ট, মূল অপারেশন:

```lua
-- 1. 清理窗口外的旧记录
redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, windowStart)
-- 2. 检查当前窗口计数
local count = redis.call('ZCARD', KEYS[1])
-- 3. 超限则返回 {0, count}，未超限则 ZADD 并返回 {1, count+1}
if count >= limit then return {0, count} end
redis.call('ZADD', KEYS[1], now, now . '.' . random)  -- 随机后缀避免同毫秒覆盖
redis.call('EXPIRE', KEYS[1], window + 10)
```

Lua স্ক্রিপ্ট Redis সার্ভার সাইডে সিঙ্গেল-থ্রেডে চলে, **স্বাভাবিকভাবেই অ্যাটমিক**, TOCTOU (Time-of-check to Time-of-use) রেস কন্ডিশন দূর করে।

### রেট লিমিট কনফিগ

| রাউট | সীমা | উইন্ডো | দৃশ্য |
|------|------|------|------|
| ডিফল্ট (সব রাউট) | ৬০ বার/মিনিট | 60s | সাধারণ API |
| `/api/v1/auth/login` | ১০ বার/মিনিট | 60s | লগইন (ব্রুট-ফোর্স প্রতিরোধ) |
| `/api/v1/auth/register` | ৫ বার/মিনিট | 60s | রেজিস্টার (বাল্ক রেজিস্টার প্রতিরোধ) |

### রেসপন্স হেডার

রেট লিমিট ট্রিগার হলে HTTP 429 ও JSON body রিটার্ন হয়:
```json
{"code": 429, "message": "请求过于频繁，请稍后再试", "data": []}
```

সব রেসপন্স (স্বাভাবিক রেসপন্সসহ) নিম্নলিখিত হেডার বহন করে:

| হেডার | বর্ণনা |
|----|------|
| X-RateLimit-Limit | বর্তমান উইন্ডোতে অনুমোদিত সর্বোচ্চ রিকোয়েস্ট সংখ্যা |
| X-RateLimit-Remaining | বর্তমান উইন্ডোতে অবশিষ্ট রিকোয়েস্ট সংখ্যা |
| X-RateLimit-Reset | উইন্ডো রিসেটের Unix টাইমস্ট্যাম্প |
| Retry-After | শুধুমাত্র রেট লিমিট হলে, অপেক্ষার সেকেন্ড সংখ্যা |

### ডিগ্রেডেশন পলিসি

Redis অস্বাভাবিক হলে (কানেকশন টাইমআউট, অনুপলব্ধ ইত্যাদি) **fail-open**:

```php
try {
    $result = Redis::eval($lua, ...);
} catch (\Throwable $e) {
    return $handler($request); // Redis down, 放行所有请求
}
```

কিছুক্ষণের জন্য রেট লিমিট সুরক্ষা হারানো সহ্য করা হয়, কিন্তু স্বাভাবিক বিজনেস রিকোয়েস্ট ব্লক করা হয় না।

### 5.4 অ্যাকাউন্ট লক মেকানিজম

লগইন ইন্টারফেস রেট লিমিটের উপরে অতিরিক্ত **অ্যাকাউন্ট লক** মেকানিজম যোগ করে, নির্দিষ্ট ইউজারকে টার্গেট করা ব্রুট-ফোর্স প্রতিরোধ করে।

**লক ফ্লো**:

```
登录失败 → Redis INCR account_lockout:{userId} TTL=900s
连续 5 次失败 → Redis SETEX account_locked:{userId} 900 1
            → 返回 429 "账号已被锁定，请15分钟后再试"
            → 清除计数器 DEL account_lockout:{userId}
```

**লক থাকা অবস্থায় আচরণ**:

লক থাকা অবস্থায় সব লগইন রিকোয়েস্ট সরাসরি 429 রিটার্ন করে, পাসওয়ার্ড ভেরিফিকেশন করা হয় না, সম্পূর্ণরূপে ব্রুট-ফোর্স প্রচেষ্টা প্রতিরোধ করে।

**কনফিগ কনস্ট্যান্ট**:

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| MAX_LOGIN_ATTEMPTS | 5 | সর্বোচ্চ টানা ব্যর্থ সংখ্যা |
| LOCKOUT_DURATION | 900 | লক ডিউরেশন (সেকেন্ড), অর্থাৎ ১৫ মিনিট |

নোট: অ্যাকাউন্ট লক `userId`-ভিত্তিক, IP নয়, তাই আক্রমণকারী IP পরিবর্তন করেও লক বাইপাস করতে পারে না। IP রেট লিমিট (১০ বার/মিনিট) এর সাথে মিলে ডাবল সুরক্ষা হয়:
- IP লেয়ার: ১০ বার/মিনিট রেট লিমিট ডিস্ট্রিবিউটেড ব্রুট-ফোর্স প্রতিরোধ করে
- অ্যাকাউন্ট লেয়ার: ৫ বার ব্যর্থ লক টার্গেটেড ব্রুট-ফোর্স প্রতিরোধ করে

## 6. অথেনটিকেশন ও অথোরাইজেশন

### 6.1 JWT অথেনটিকেশন

AdminAuth মিডলওয়্যারে ইমপ্লিমেন্টেড, অথেনটিকেশন প্রয়োজন এমন রাউট গ্রুপে মাউন্ট করা।

**প্যারামিটার কনফিগ** (`config/plugin/erikwang2013/jwt/jwt`, `.env` থেকে ইনজেক্ট):

| প্যারামিটার | মান | বর্ণনা |
|------|-----|------|
| অ্যালগরিদম | HS256 | HMAC-SHA256 সিমেট্রিক সিগনেচার |
| সিক্রেট কী | `JWT_SECRET` | এনভায়রনমেন্ট ভেরিয়েবল থেকে ইনজেক্ট, প্রোডাকশনে পরিবর্তন প্রয়োজন |
| access_token TTL | 7200s (2h) | `JWT_TTL` |
| refresh_token TTL | 1209600s (14d) | `JWT_REFRESH_TTL` |
| ইস্যুয়ার | `open-admin` | `JWT_ISSUER` |
| অডিয়েন্স | `open-admin` | `JWT_AUDIENCE` |

**Token এক্সট্রাকশন**: `Authorization: Bearer <token>` হেডার থেকে, `Bearer ` প্রিফিক্স স্ট্রিপ করে অরিজিনাল JWT পাওয়া যায়।

**অথেনটিকেশন ফ্লো**:
1. খালি token → সরাসরি 401 `{"code": 401, "message": "未登录"}`
2. Redis ব্ল্যাকলিস্ট `jwt_blacklist:{md5(token)}` চেক → হিট → 401 `Token已失效，请重新登录`
3. JWT decode → ব্যর্থ (মেয়াদোত্তীর্ণ/সিগনেচার মিলছে না) → 401 `Token已过期或无效`
4. সফল → `$request->adminId` ও `$request->adminUsername` ইনজেক্ট

**ব্ল্যাকলিস্ট মেকানিজম**: ইউজার লগআউট করলে `md5(token)` Redis-এ লেখা হয়, TTL JWT-এর অবশিষ্ট বৈধতা সময় হয়। Redis ব্যর্থ হলে ব্ল্যাকলিস্ট চেক স্কিপ হয় (fail-open), এই অবস্থায় লগআউট করা Token অল্প সময় ব্যবহার করা যায়, কিন্তু JWT-এর ছোট মেয়াদ (2h) ব্যাকআপ সুরক্ষা হিসেবে থাকে।

### 6.2 কনকারেন্ট সেশন সীমা

Token লিক হওয়ার পর মাল্টি-ডিভাইস অপব্যবহার প্রতিরোধ করতে, সিস্টেম একই ইউজারের একসাথে থাকা সক্রিয় Token সংখ্যা সীমিত করে।

**সীমা লজিক**:

```
登录成功 → 签发新 Token
         → 查询当前用户有效 Token 数量: Redis SCARD user_tokens:{userId}
         → 若数量 >= 3（MAX_CONCURRENT_SESSIONS）:
            → 按创建时间升序排列，移除最旧的 Token:
              Redis SREM user_tokens:{userId} <oldest_token_id>
              Redis SETEX jwt_blacklist:{md5(oldest_token)} TTL remaining
         → 将新 Token 加入集合: Redis SADD user_tokens:{userId} <new_token_id>
            Redis SET user_token:{token_id} {userId} EX {TTL}
```

**কনফিগ কনস্ট্যান্ট**:

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| MAX_CONCURRENT_SESSIONS | 3 | একই ইউজারের সর্বোচ্চ কনকারেন্ট Token সংখ্যা |

**বাধ্যতামূলক লগআউট দৃশ্য**: ইউজার ৪র্থ ডিভাইসে লগইন করলে, ১ম ডিভাইসের Token ব্ল্যাকলিস্টে বাধ্যতামূলক যায়, পরের রিকোয়েস্টে 401 "Token已失效，请重新登录" রিটার্ন হয়।

লগআউট করলে বর্তমান Token সেট থেকে সরানো হয়। Token স্বাভাবিকভাবে মেয়াদোত্তীর্ণ হলে Redis key অটো মেয়াদোত্তীর্ণ হয়, সেট সদস্য সেই অনুযায়ী কমে।

### 6.3 RBAC পারমিশন মডেল

AdminPermission মিডলওয়্যারে ইমপ্লিমেন্টেড।

**ডেটা মডেল**: User -> Role -> Permission তিন লেয়ারের সম্পর্ক

- `logistics_admin_user` (ইউজার টেবিল)
- `logistics_admin_user_role` (ইউজার-রোল সম্পর্ক টেবিল)
- `logistics_admin_role` (রোল টেবিল)
- `logistics_admin_role_permission` (রোল-পারমিশন সম্পর্ক টেবিল)
- `logistics_admin_permission` (পারমিশন টেবিল)

**পারমিশন টাইপ**:
| type | অর্থ | উদাহরণ |
|------|------|------|
| 1 | মেনু পারমিশন | বাম নেভিগেশনের দৃশ্যমানতা নিয়ন্ত্রণ |
| 2 | বাটন পারমিশন | পেজের ভেতরের অপারেশন বাটন নিয়ন্ত্রণ (নতুন/এডিট/ডিলিট) |
| 3 | API পারমিশন | ব্যাকএন্ড ইন্টারফেস কল নিয়ন্ত্রণ |

API পারমিশন আইডি ফরম্যাট: `{method}.{path}`

উদাহরণস্বরূপ:
- `post.admin/user` — ইউজার তৈরি
- `put.admin/user` — ইউজার এডিট
- `delete.admin/user` — ইউজার ডিলিট
- `get.admin/user` — ইউজার লিস্ট দেখা

**অথোরাইজেশন ফ্লো**:
1. `$request->adminId` খালি → অনুমোদন (রাউটে অথেনটিকেশন প্রিফিক্স কনফিগ করা নেই)
2. ইউজার → রোল (status=0-এর নিষ্ক্রিয় রোল বাদে) → পারমিশন লিস্ট প্রাপ্তি
3. সুপার অ্যাডমিন (`slug = '*'`) → সরাসরি অনুমোদন
4. `strtolower(method) . '.' . trim(path, '/')` নির্মাণ → পারমিশন লিস্টের সাথে তুলনা
5. ম্যাচ ব্যর্থ → 403 `{"code": 403, "message": "无权限访问"}`

**দ্বিতীয় নিশ্চিতকরণ**: BaseController `confirmPassword()` মেথড দেয়, সংবেদনশীল অপারেশনে (ইউজার ডিলিট, ডেটা এক্সপোর্ট ইত্যাদি) Controller লেয়ারে অতিরিক্ত বর্তমান পাসওয়ার্ড ইনপুট চায়, সেশন হাইজ্যাকের পর অননুমোদিত অপারেশন প্রতিরোধ করে।

## 8. ডেটা সুরক্ষা

সিস্টেম তিন লেয়ারের ডেটা সুরক্ষা পলিসি ব্যবহার করে, ডেটা প্রবাহের তিনটি ধাপের সাথে মিলে যায়।

### 8.1 ট্রান্সপোর্ট লেয়ার — EncryptionService

`EncryptionService` `erikwang2013/encryption` প্যাক ব্যবহার করে, API রিকোয়েস্ট/রেসপন্সের সংবেদনশীল ফিল্ড এনক্রিপ্ট/ডিক্রিপ্ট করে।

**প্রযুক্তিগত বিবরণ**:
- অ্যালগরিদম: `aes-256-cbc-hmac` (বিল্ট-ইন HMAC সিগনেচার, টেম্পার প্রতিরোধ)
- সিক্রেট কী: `ENCRYPTION_KEY` এনভায়রনমেন্ট ভেরিয়েবল, অটো ৩২ বাইটে অ্যালাইন
- ব্যবহার: ক্লায়েন্ট ও API-এর মধ্যে ফোন নম্বর, আইডি কার্ড নম্বর ইত্যাদি ফিল্ড ট্রান্সমিট

**মাস্কিং টুল মেথড**:
- `maskPhone('13812341234')` → `138****1234`
- `maskEmail('abc@example.com')` → `a***@example.com` (ইউজারনেম ২ অক্ষরের বেশি হলে) বা `a**@example.com`

### 8.2 স্টোরেজ লেয়ার — Encryptable Cast

`AdminUser` মডেল `Erikwang2013\Encryptable\Encryptable` Eloquent cast ব্যবহার করে, সংশ্লিষ্ট ফিল্ড:

- `email` → cast Encryptable, অটো এনক্রিপ্ট/ডিক্রিপ্ট
- `phone` → cast Encryptable, অটো এনক্রিপ্ট/ডিক্রিপ্ট
- `id_card` → cast Encryptable, অটো এনক্রিপ্ট/ডিক্রিপ্ট

ডেটাবেসে লেখার সময় অটো সাইফারটেক্সটে এনক্রিপ্ট হয়, পড়ার সময় অটো প্লেইনটেক্সটে ডিক্রিপ্ট হয়। ডেটাবেস স্টোরেজ কলাম টাইপ `VARCHAR(500)`, সাইফারটেক্সট base64 ফর্মে সংরক্ষিত।

**সিক্রেট কী সিস্টেম**: ট্রান্সপোর্ট লেয়ার এনক্রিপশন (`ENCRYPTION_KEY`) থেকে আলাদা `ENCRYPTABLE_KEY` ব্যবহার হয়, একটি কী লিক হলে অন্য লেয়ার ক্ষতিগ্রস্ত হয় না।

সিক্রেট কী রোটেশন: `ENCRYPTION_PREVIOUS_KEYS` এনভায়রনমেন্ট ভেরিয়েবল হিস্ট্রিক কী লিস্ট সাপোর্ট করে (কমা দিয়ে আলাদা), পুরনো ডেটা পড়ার সময় হিস্ট্রিক কী দিয়ে ডিক্রিপ্ট চেষ্টা হয়, লেখার সময় বর্তমান কী দিয়ে পুনরায় এনক্রিপ্ট।

### 8.3 প্রেজেন্টেশন লেয়ার — ID অবফাসকেশন ও মাস্কিং

**Hashids ID অবফাসকেশন**: `HashidsService` `erikwang2013/hashids` প্যাক ব্যবহার করে।

- বাইরের API-তে রিটার্ন করা ডেটাবেস BIGINT ID hash স্ট্রিংয়ে এনকোড হয় (যেমন `xK3mN9qR2pL7wV8b`)
- ক্লায়েন্ট রিকোয়েস্টে hash স্ট্রিং পাঠায়, ব্যাকএন্ড অটো অরিজিনাল ID-তে ডিকোড করে
- সল্ট `HASHIDS_SALT` এনভায়রনমেন্ট ভেরিয়েবল থেকে ইনজেক্ট, সল্ট ভিন্ন হলে এনকোড/ডিকোড রেজাল্ট সম্পূর্ণ ভিন্ন
- hash ন্যূনতম দৈর্ঘ্য ১৬ অক্ষর, ৬২-অক্ষরের অ্যালফানিউমেরিক ক্যারেক্টার সেট
- BaseController `encodeId()`, `decodeId()`, `encodeIds()` কনভিনিয়েন্ট মেথড দেয়

## 9. সিক্রেট কী ম্যানেজমেন্ট

সব সিক্রেট কী `.env` এনভায়রনমেন্ট ভেরিয়েবল থেকে ইনজেক্ট হয়, কনফিগারেশন ফাইল `getenv()` দিয়ে পড়ে এবং বিল্ট-ইন ফলব্যাক ডিফল্ট মান রাখে (শুধুমাত্র ডেভেলপমেন্ট পরিবেশে নিরাপদ)।

- `.env` ফাইল `.gitignore`-এ যোগ করা, ভার্সন কন্ট্রোলে কমিট করা কঠোরভাবে নিষিদ্ধ

- `openssl rand -base64 32` দিয়ে সিক্রেট কী জেনারেট করার পরামর্শ দেওয়া হয়

## 10. security.txt (RFC 9116)

সিস্টেম `/.well-known/security.txt`-এ RFC 9116 স্ট্যান্ডার্ড মেনে সিকিউরিটি কন্টাক্ট তথ্য এন্ডপয়েন্ট দেয়, সিকিউরিটি রিসার্চাররা দুর্বলতা পেলে দ্রুত রিপোর্ট চ্যানেল খুঁজে পায়।

**অ্যাক্সেস পদ্ধতি**:

```
GET /.well-known/security.txt
```

**রেসপন্স কনটেন্ট**:

```text
Contact: mailto:security@erik.xyz
Expires: 2027-05-20T00:00:00.000Z
Preferred-Languages: zh, en
Canonical: https://erik.xyz/.well-known/security.txt
Policy: https://erik.xyz/security-policy
```

**ফিল্ড বর্ণনা**:

| ফিল্ড | বর্ণনা |
|------|------|
| Contact | নিরাপত্তা দুর্বলতা রিপোর্টের যোগাযোগ উপায় |
| Expires | ফাইলের মেয়াদোত্তীর্ণ সময়, নিয়মিত আপডেট প্রয়োজন |
| Preferred-Languages | পছন্দের যোগাযোগ ভাষা |
| Canonical | এই ফাইলের ক্যানোনিকাল URL |
| Policy | নিরাপত্তা পলিসি/দুর্বলতা ডিসক্লোজার পলিসি লিংক |

এই এন্ডপয়েন্ট রেট লিমিট, অথেনটিকেশন ইত্যাদি মিডলওয়্যারের আওতাভুক্ত নয়, যে কেউ সরাসরি অ্যাক্সেস করতে পারে।

## 11. Nginx নিরাপত্তা কনফিগারেশন

প্রজেক্ট `docs/nginx-security.conf` প্রোডাকশন পরিবেশের Nginx রিভার্স প্রক্সির নিরাপত্তা হার্ডেনিং রেফারেন্স কনফিগ হিসেবে দেয়।

**অন্তর্ভুক্ত নিরাপত্তা ব্যবস্থা**:

| কনফিগ আইটেম | কাজ |
|--------|------|
| `server_tokens off` | Nginx ভার্সন নম্বর লুকানো |
| `client_max_body_size 10m` | রিকোয়েস্ট বডি সাইজ সীমিত, SecurityMiddleware (erikwang2013/security-php)-এর সাথে সমন্বয় |
| `limit_req_zone` | Nginx লেয়ারে রিকোয়েস্ট ফ্রিকোয়েন্সি লিমিট |
| `limit_conn_zone` | কনকারেন্ট কানেকশন সংখ্যা সীমা |
| `add_header` সিকিউরিটি হেডার | Nginx লেয়ারে X-XSS-Protection ইত্যাদি সিকিউরিটি হেডার যোগ |
| `if ($request_method)` | Nginx লেয়ারে নন-স্ট্যান্ডার্ড HTTP মেথড রিজেক্ট |
| SSL/TLS কনফিগ | আধুনিক TLS 1.2/1.3 কনফিগ, দুর্বল সাইফার সুইট নিষিদ্ধ |
| ব্যাকএন্ড হেডার লুকানো | `proxy_hide_header` দিয়ে webman ভার্সনের মতো সংবেদনশীল হেডার সরানো |

**ব্যবহার পদ্ধতি**: `docs/nginx-security.conf`-এর কনফিগ আপনার Nginx server ব্লকে মার্জ করুন, প্রকৃত ডোমেইন ও সার্টিফিকেট পাথ অনুযায়ী অ্যাডজাস্ট করুন।

## 13. ক্লায়েন্ট পোর্টাল ও পেমেন্ট নিরাপত্তা (M7–M10)
Stripe / PayPal ওয়েবহুক সিগনেচার যাচাই (HMAC-SHA256 / verify-webhook-signature)；পেমেন্ট কী `Encryptable` দিয়ে এনক্রিপ্ট করে `logistics_system_config`-এ সংরক্ষণ；USDT TRC20 Tronscan দিয়ে স্বয়ংক্রিয় যাচাই, BEP20 / ERC20 ম্যানুয়াল；X-API-Key ক্লায়েন্ট নিজেই সেট করে (≥১৬ অক্ষর), sha256 হিসেবে সংরক্ষণ। গেটওয়ে আক্রমণ সনাক্তকরণ (M11): `ecat-security` SecurityBodyLayer গেটওয়েতে সংহত, আক্রমণের পেলোড গেটওয়ে স্তরেই আটকানো হয়। **13.5 CDN নিরাপত্তা (M12)**: Cloudflare ফ্রি প্ল্যান সম্পূর্ণ HTTPS + দ্বি-স্তর WAF (এজ ম্যানেজড রুল + গেটওয়ে অ্যাপ্লিকেশন স্তর সনাক্তকরণ); Tunnel অরিজিনে সোর্স শূন্য এক্সপোজার; কলব্যাক কেবল DNS সাবডোমেইন সরাসরি সংযোগে, CDN ব্যর্থতায় অর্ডার হারানো এড়ানো; রেট লিমিট X-API-Key অনুযায়ী, CDN এজ আইপি দ্বারা প্রভাবিত নয়; প্রমাণিত এন্ডপয়েন্ট সর্বদা no-store, ক্রস-ইউজার ক্যাশ মিক্সিং প্রতিরোধ। **13.6 CDN প্রদানকারী কী ব্যবস্থাপনা (M13)**: CDN প্রদানকারী প্রোফাইল (access_key / access_secret / ডোমেইন তালিকা) `logistics_cdn_provider` টেবিলে, গোপন ফিল্ড `Encryptable` দিয়ে এনক্রিপ্ট, `/admin/cdn/provider` CRUD দিয়ে রক্ষণাবেক্ষণ।
